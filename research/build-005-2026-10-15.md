# Native MOS foundation: first implementation tranche

The new private foundation builds directly from readable, maintained source.
Its ROM matches the selected stock AgonDev control byte-for-byte, with identical
public symbol addresses and unchanged C objects. Maintainers no longer need
to edit ZDS source and regenerate this fork for routine development. This is
an offline-verified review candidate, not a qualified firmware release or an
EMOS adoption; installed firmware and the UART project are unchanged.

The Author authorized this tranche on 2026-10-15 under
[BUILD-005](../docs/tasks/BUILD-005.md). Initial guidance/contract publication
is complete; new implementation remains uncommitted for review, as specified
in that tranche. This report is evidence, not an additional actionable task list.

## 2. Maintainer-readable source and provenance

The fork preserves original module paths, routine names, comments, licenses
and full official ancestry. It compiles 16 C units and assembles 15 original
roots. Twenty assembly/include files retain recognizable native macros and
include structure instead of flattened expansions. GNU private labels name
their routines, anonymous branches use `1f`/`1b`, and macro-local labels use
`\@` to keep invocations independent. GNU file-local binding is not claimed
to recreate ZDS procedure scopes automatically.

The source repository supplies its own root `STARTHERE.md`, Makefile, explicit
`build.json`, ownership/agent guidance, and source-owned tests. Dependency
locations are selectable; ignored `.local/` defaults do not require the
Author's sibling-directory layout. Its project `.venv` exists locally; fresh
clone instructions explain how to create one, with no package requirements.

Traceability lives beside the maintained source:

1. `docs/upstream-origin.md` identifies the exact official ancestry and
   historical ZDS files versus current GNU source/build inputs.
2. `docs/deviations.md` records 12 stable deviation IDs, reasons and removal
   conditions. Unusual C/branch/include changes have focused source comments.
3. `docs/migration/initial-map.json` records original/native assembly hashes,
   original line origins, macro names and local-symbol correspondences.
   It is a frozen migration receipt, not a future regeneration input or a
   demand that ongoing edits retain the original hashes forever.
4. `docs/migration/upstream-files.json` inventories all 66 original tracked
   files and their first-tranche counterparts; 30 changed, including syntax,
   portability and onboarding edits. Git history remains the original authority.
5. `docs/migration/first-tranche.json` records this candidate's control,
   tests, consumed-helper hashes and explicit absence of runtime qualification.

Mechanical conversion and readability were built separately in the persistent
workspace. Keep those concerns reviewable when source commits are promoted;
do not mix a new behavior fix into migration under an equivalence claim.

## 3. Reusable tools and tests

The local [native foundation helpers](../projects/native-foundation/README.md)
have distinct purposes: one-time pinned migration, direct maintained-source
build, and exact binary/public-symbol comparison. The existing frontend remains
corpus-driven; this work is not a complete ZDS implementation or a general
converter for arbitrary applications. Normal native builds import neither the
migrator nor the frontend and never overwrite source from a generated copy.

The direct builder reuses existing runtime, provenance and linker authorities.
It verifies overlapping SDK hardware constants, pinned compiler/runtime,
restricted runtime closure, i48 helpers, formatter usage/host golden cases and
final image guards. Every declared product-owned linked-image checker runs
against the selected source and final ELF; failures cannot be skipped. Source,
tool, helper and checker drift is rejected. Fresh output directories retain
failures, target command/dependency receipts, runtime audit, logs and artifacts.

Focused passing suites total **49 tests**:

1. 19 new migration, profile, checker-failure and binary/public-symbol tests.
2. Six native-source ancestry, mapping, macro, build-boundary and deviation tests.
3. Twenty shared target-provenance regressions.
4. Four shared source-profile regressions.

This is not a claim that the complete legacy suite was rerun or is green. The
previously recorded Binutils 2.45 backward-JR display defect remains in
[upstream findings](../docs/upstream-findings.md); raw encoding and exact image
equality avoid relying on that erroneous displayed target. No unrelated
translator or emulator behavior was changed to hide an existing failure.

## 4. Reproduction and evidence

From the new native repository, the measured final build used these
project-relative selections; substitute your own independent dependency paths:

```bash
make baseline-check MOS_AGONDEV_ROOT=../mos-agondev \
  AGONDEV_TOOLCHAIN=../worktrees/emos-build-003/tools/agondev \
  REFERENCE_BIN=../worktrees/mos-build-004/evidence/stock-agondev/MOS.bin \
  BUILD_DIR=.build/first-tranche-proof
```

Choose a **fresh** BUILD_DIR when repeating the run. The final root command
took 13.24 seconds on the local Linux host, including checks. Mechanical and
readable controls took 11.98 and 11.92 seconds. These are host build durations,
not firmware performance, cross-machine clock calibration or automatic timeouts.
The pin is Clang 15.0.7 / LLVM `c76386c0083e6a6236ff774275227e2389f85538`,
Binutils 2.45, and libagon.a SHA-256
`5de7878342ab6780593fbf8d54d8005960e2471bd0e34c0e307fbcfe42fef28a`.

Persistent investigation workspace: `../worktrees/mos-build-005/`, relative to
this project root. It retains mechanical/readability source controls, failed
diagnostic runs, build/test command logs, exact comparison, summary, finalizer
and artifact inventory. The actual native repository's ignored
