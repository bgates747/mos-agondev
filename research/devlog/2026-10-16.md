# Policy consolidation and canonical API decisions

Project policy now has one authority, `docs/POLICIES.md`. It preserves the
accepted native-source direction and records the Author's canonical-interface,
allocation-reservation and firmware/build-identity decisions. This is a
documentation update, not implementation or release qualification.

1. Moved the native-foundation policy into the consolidated document, retaining
   the old path as a redirect so historical and cross-owner links still work.
   Updated onboarding, agent guidance, ownership pointers and the technical
   index. The assembly strategy now explicitly describes retained translation
   behavior rather than competing native-development policy.
2. Canonical assembly/C interfaces own numeric allocations; projects reserve
   carveouts there and consume the versioned shared files instead of making
   private variants. MOS calls and getfunction indices remain distinct.
3. Firmware builds provide one identity record for banner and distributed
   interfaces: product/version, full source commit, dirty status and separate
   API-definition version. Application builds consume it without stamping a
   different firmware identity. Compile-time identity does not prove the
   firmware installed at runtime.
4. API-001 records unfinished implementation in the sole TODO. No new numeric
   assignment, shared SDK mutation, consumer migration, metadata generator,
   runtime query, firmware build or emulator/hardware operation occurred.
   The qsort API experiment remains excluded. Owner contracts and technical
   specifications retain their separate stated authority.
5. Changes remain local and uncommitted. Existing unrelated work and frozen
   migration evidence were preserved; no commit, push or publication requested.
