## Experiments and decisions

4. **DL-004:** Built a custom AgonDev firmware probe. The result is ELF32 Z80
   with eZ80 ADL flags, entry zero, the required fixed ROM/RAM layout, and a raw
   binary SHA-256 of
   `28528ac57eb024dfa2afad063db102cb11d115c87c2d3dfaf65bdb27a47647a9`.
   Static assertions and disassembly confirm 16-bit `short`, 24-bit
   `int`/pointer, 32-bit `long`, and the documented three-byte stack ABI.
5. **DL-005:** A direct GNU assembler attempt on current ZDS assembly failed on
   its numeric literal and macro dialect. The audited assembly/include surface
   is 6,680 lines. The eZ80 opcodes themselves are supported; conversion work is
   primarily directives, macros, labels, literals, sections, and pseudo-ops.
6. **DL-006:** Generated code for all 16 C translation units from a disposable
   tracked-file copy. Five small compatibility edits were necessary. FatFS
   `ff.c` exhausts AgonDev's register allocator at `-Oz` and `-O1`, but succeeds
   at `-Os`; the per-file workaround is retained in the probe.
7. **DL-007:** The initial AgonDev C objects contained 87,285 bytes of
   text/rodata plus 735 initialized bytes, or 88,020 loadable bytes before
   runtime and assembly. The explicit `quickrand` return contract later raised
   the maintained C-probe total by 34 bytes to 88,054.
   Comparable current ZDS C modules occupy 95,238 loadable bytes. This is
   encouraging but not a final image-size comparison because runtime selection
   and ported assembly can change both totals.
8. **DL-008:** Selected an explicit firmware-runtime policy rather than stock
   AgonDev application integration. The application CRT is unsuitable inside
   MOS. The default formatter and weak `putchar` also need replacement or
   configuration because MOS uses 32-bit formats and raw newline behavior.
9. **DL-009:** Created an ignored, isolated emulator profile around the installed
   stock Platform MOS/VDP. A future AgonDev MOS must supply Fab's ROM descriptor
   table, a ZDS-compatible map bridge, or a raw SD image; Fab cannot interpret a
   normal GNU linker map for directory-backed SD access.

    this point the decision remained provisional pending deterministic
    translation, diagnostics, object, relocation, disassembly, and

15. **DL-015:** The author interactively launched the project-local stock

16. **DL-016:** Implemented the first ongoing ZDS compatibility frontend. It

17. **DL-017:** Implemented and isolated the production linker contract. Its
