# Stock MOS, EMOS and UART: controlled toolchain size comparison

Stock MOS has roughly 26–29 KB of ROM space available in the measured
size-oriented builds. The tight budget belongs to EMOS, not stock MOS. The
selected interrupt-driven UART addition costs exactly 2,573 ROM bytes and
86 RAM bytes on stock MOS under all three measured configurations. AgonDev
already translates its assembly correctly; no new translator or product-source
patch was needed. EMOS integration is still absent and requires a separate
Author decision before work begins.

This is the Stages 1–3 result for [BUILD-004](../docs/tasks/BUILD-004.md), not
a firmware release or runtime acceptance. No hardware or emulator was run or
changed. The Author released this offline tranche on 2026-10-15; Stage 4 remains
unreleased. Toolchain policy remains undecided.

## 1. Comparable measurements

All numbers below are ROM address extents in **bytes**, against a 131,072-byte
capacity. They include internal gaps and initialized-data ROM copies, but no
terminal padding to a complete ROM. Native ZDS speed and size profiles are
separate controls; AgonDev uses `-Oz`, with `ff.c` at `-Os`.

| Identical source variant / explicit compatibility control | AgonDev | ZDS size | ZDS speed |
| --- | ---: | ---: | ---: |
| Stock MOS v3.0.2 | 102,055 | 104,798 | 108,490 |
| Stock MOS + UART ABI1.2 | 104,628 | 107,371 | 111,063 |
| EMOS v0.1.24 with the two native-C compatibility edits | 128,574 | 134,649, over capacity | 138,887, over capacity |
| EMOS + UART | Not implemented | Not implemented | Not implemented |

The exact installed EMOS AgonDev build remains **128,622 bytes**, leaving
**2,450 bytes**. The compatibility-control AgonDev build is 48 bytes smaller:
ZDS requires structure-copy initialization to become `memcpy`, and a command
fallback block's declarations to precede executable statements. Applying those
same two edits to AgonDev supplies the matched-input row above; it does not
relabel the installed firmware or establish behavioral qualification of the edits.
Native EMOS identity strings also match the installed build, rather than the
unversioned placeholders in the original assessment.

| Source variant | AgonDev ROM headroom | ZDS size headroom | ZDS speed headroom |
| --- | ---: | ---: | ---: |
| Stock MOS | 29,017 | 26,274 | 22,582 |
| Stock + UART | 26,444 | 23,701 | 20,009 |
| EMOS compatibility control | 2,498 | −3,577 | −7,815 |

The native EMOS links retain fatal range/overlap guards and exit 255. Their HEX
and maps are analysis evidence only. Stock and stock-UART links succeed under
all three configurations. This does not establish equivalent runtime behavior.
The fresh native stock build uses the frozen UART owner's build recipe against
clean official source; it is not claimed to reproduce the distributed upstream
release binary byte-for-byte.

## 2. What the feature costs

Subtract each addition from its own same-toolchain, same-profile foundation:

| Addition | AgonDev ROM increase | ZDS size increase | ZDS speed increase |
| --- | ---: | ---: | ---: |
| UART ABI1.2 on stock | 2,573 | 2,573 | 2,573 |
| EMOS native-compatible source over stock | 26,519 | 29,851 | 30,397 |

The installed-source EMOS AgonDev increase is 26,567 bytes; the 48-byte
compatibility-control difference explains the separate number above. EMOS adds
1,286 bytes to the measured AgonDev RAM allocation span and 1,316 under ZDS.
These are static allocation spans, **not** a claim about safe heap/stack headroom.

UART's complete ROM delta is identical in all configurations:

| Module | ROM delta, bytes |
| --- | ---: |
| uart0_async | +2,497 |
| serial | +33 |
| crash | +21 |
| mos_api | +14 |
| vectors16 | +14 |
| misc | +8 |
| main | +4 |
| vdp_protocol | +4 |
| interrupts | −22 |
| **Total** | **+2,573** |

All other source-module contributions and the linked runtime size remain
unchanged. All AgonDev C objects except `main.o` are byte-identical between
stock and stock-UART. The linked UART object's 86-byte BSS **includes** its
one-byte synchronization-depth field at offset 85; it is not 86 plus another
byte. This resolves an ambiguity in the owner's initial RAM description.

| Static RAM allocation span, bytes | AgonDev | ZDS, either profile |
| --- | ---: | ---: |
| Stock | 2,779 | 3,029 |
| Stock + UART | 2,865 | 3,115 |
| EMOS compatibility control / installed source | 4,065 | 4,345 |

ZDS size exceeds AgonDev by 2,743 bytes for both stock variants, and by 6,075
for matched-input EMOS. In every ordinary configuration, ZDS runtime modules
total 5,216 bytes versus AgonDev's 5,773: **ZDS's runtime is 557 bytes smaller**.
The size advantage comes from the combined source-generated code/data, not a
blanket claim that AgonDev's libraries are smaller. Per-module and section
attribution is retained in the workspace JSON reports.

## 4. Translation and offline checks

The comparison replays **explicit GNU object relocation records** using native
ZDS module and symbol addresses, then compares the resulting bytes. It does not
mask arbitrary values merely because they resemble pointers. Unknown relocation
kinds, overlapping writes or unmapped section references fail closed.

All explicitly emitted handwritten assembly bytes match: 8,008 for stock and
10,577 for stock-UART, replaying 1,037 and 1,355 relocations respectively. This
includes the complete 2,497-byte UART core/wrapper/table. Native ZDS separates
SD's 30-byte command constants into TEXT while GNU keeps them in `.text`; the
comparison accounts for both ranges. Native reset reserves 71 bytes without HEX
records, whereas GNU emits fill bytes: those implicit native bytes are excluded,
not asserted equal. Fab's descriptor occupies the existing 149-byte reset/vector
gap and adds no image extent.

Passing checks include:

1. 11 comparison regressions: relocation replay/rejection, HEX accounting,
   signed backward-branch encoding, deterministic UART translation, unchanged
   C-object inventory, full assembly comparison, complete 54-byte linked UART
   ABI table and pointers, batch bitmap, BSS layout and matched feature deltas.
2. Seven source-diagnostic mapping tests and four source-profile tests.
3. Both root `firmware-check` runs, including runtime-policy/formatter host
   checks, helper audits and linker guards. All 16 C units' compiler-emitted
   assembly was also retained for each stock variant.

There are **known test failures**, not an entirely green repository suite:

1. The stock frontend suite passes 23 of 24 tests. The remaining existing test
   expects a correctly displayed backward JR target; the retained objdump prints
   `0108h` instead of `0008h` for the correctly encoded `18 FD` instruction at
   offset 9. A minimal fixture and raw bytes reproduce it independently.
2. Running the stock-only corpus test against UART additionally fails its fixed
   15-unit assertion because UART legitimately has 16 units. The independent
   UART determinism test and full assembled-byte check cover the actual extended
   corpus without changing the stock fixture's expected counts.

The disassembler finding is recorded in
[upstream findings](../docs/upstream-findings.md#agondev-binutils-001--backward-jr-target-is-displayed-256-bytes-too-high).
Neither failure is silently skipped or represented as a successful full suite.
No new emulator, hardware, timing, CTS-headroom, callback or application-lifetime
qualification is claimed. Correct translation preserves the candidate's source;
it does not prove the source algorithm correct.

## 5. Implications and review boundary

The stock UART feature's size is effectively toolchain-independent at this
revision. The remaining size discrepancy belongs to the foundations' C/data
generation and runtime composition. Switching compilers alone does not make
UART smaller; it changes how much room the underlying product has available.

A simple planning sum puts installed EMOS plus the stock UART delta 123 bytes
over ROM capacity; the native-compatible AgonDev control would be 75 bytes over.
**Neither is an integration measurement.** EMOS-specific replacements, routing
guards and hooks can change the actual cost. The 130,044-byte optimized native
experiment from BUILD-003 would be 1,545 bytes over by the same naive sum and
still has its own runtime-qualification gate. No features or diagnostics were
removed to obtain the results here.

Recommendation: review these results before releasing Stage 4. If released,
coordinate a Legacy-first integration with both source owners and preserve
EMOS's UART1 transport, route/admission ownership, callbacks, barriers and return
fences. Establish the actual integrated budget before choosing compaction changes
or a primary release toolchain. Generic findings do not authorize bypassing EMOS
or merging the stock UART module wholesale into maintained EMOS.
